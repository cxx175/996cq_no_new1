## Why

`tool.cpp` 文件目前有 3543 行代码，存在大量重复的代码模式和可以优化的结构。通过分析发现以下主要问题：

1. **代码重复严重**：存在多个相似的 AES 加密/解密函数，字符串处理逻辑重复
2. **函数过长**：单个函数超过 200 行，难以维护和测试
3. **缺乏模块化**：所有功能混在一个文件中，职责不清晰
4. **错误处理重复**：相似的错误处理逻辑在多处重复
5. **性能问题**：存在不必要的字符串拷贝和内存分配

## What Changes

- **BREAKING**: 重构 `tool.cpp` 文件，将其拆分为多个功能模块
- **BREAKING**: 统一加密/解密接口，消除重复的 AES 实现
- **BREAKING**: 创建通用的字符串处理工具类
- **BREAKING**: 重构文件操作函数，提供统一的错误处理
- **BREAKING**: 优化内存使用，减少不必要的字符串拷贝
- 保持现有 API 兼容性，通过内部重构提升代码质量

## Impact

- **受影响的功能规格**: `specs/app/spec.md` - 核心应用功能
- **受影响的代码**: 
  - `app/src/main/cpp/tool.cpp` - 主要重构目标
  - `app/src/main/cpp/tool.h` - 头文件需要相应更新
  - 可能影响使用这些函数的其他 C++ 文件
- **性能提升**: 减少内存分配，提高函数执行效率
- **维护性提升**: 代码结构更清晰，便于后续维护和扩展
- **测试覆盖**: 模块化后更容易进行单元测试
