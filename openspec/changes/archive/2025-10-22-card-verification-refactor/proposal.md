# 卡密验证系统重构提案

## Why

当前项目使用自定义的卡密验证API (`http://gmcdk.top/sql/TongYongcdk/index.php`)，存在以下问题：
1. **安全性不足**：缺乏标准的签名验证机制
2. **标准化缺失**：不符合行业标准的API规范
3. **维护困难**：自定义API难以维护和扩展
4. **兼容性问题**：与标准卡密验证系统不兼容

需要重构为标准的权朗网络API3.0格式，以提供更好的安全性、标准化支持和长期维护性。

## What Changes

基于权朗网络API3.0规范，将当前项目的卡密验证系统完全重构为标准的卡密验证流程。新的系统将支持卡密登录、卡密心跳、卡密退出等完整功能，并采用统一的JSON响应格式。

## 技术规范

### API端点
- **时间戳获取**: `GET https://域名/time`
- **卡密登录**: `POST 域名/apiv3/card_login`
- **卡密心跳**: `POST 域名/apiv3/card_heartbeat` 
- **卡密退出**: `POST 域名/apiv3/card_logout`

### 多服务器支持
- **主服务器**: `https://napi.2cccc.cc`
- **备用服务器1**: `http://api2.2cccc.cc`
- **备用服务器2**: `http://api3.2cccc.cc`
- **故障转移**: 随机选择服务器，JSON验证失败时自动切换
- **重试机制**: 最多20次重试，防止DDOS攻击影响

### 公共参数（所有接口必需）
- `center_id`: 812700 (开发者ID)
- `timestamp`: 时间戳 (从域名/time获取)
- `sign`: 签名值 (MD5加密结果)

### 开发者配置
- **center_id**: 812700
- **apipassword**: 124600
- **software**: QLBT

### 签名算法
1. **请求签名**: `MD5(apipassword + timestamp)` - API密码在前，时间戳在后
2. **响应验证**: `MD5(timestamp + apipassword)` - 时间戳在前，API密码在后
3. **时间戳验证**: 必须在60秒内有效

### 请求参数
- `card`: 卡密内容 (必填)
- `software`: 软件名 (必填)
- `needle`: 登录标识 (心跳和退出时使用)

### 响应格式

**成功响应 (code="1")**:
```json
{
  "code": "1",
  "data": {
    "type": "年",
    "endtime_timestamp": 1558022400,
    "endtime": "2019-05-17 00:00:00", 
    "less_time": "【111】天【22】小时【40】分钟【57】秒",
    "needle": "iWG1We92sK"
  },
  "time": 1548350343,
  "sign": "b6da39d4b1fc336cddc15bd041ea9cb5"
}
```

**失败响应 (code="0")**:
```json
{
  "code": "0",
  "msg": "密码错误"
}
```

### 安全防护机制
- **反破解保护**: 请求签名和响应验证使用不同算法
- **网络层保护**: JSON格式验证，防止篡改
- **服务器容灾**: 多服务器随机选择，自动故障转移
- **重试限制**: 最多20次重试，防止资源耗尽
